# Работа с 3x Mobile

Android-приложение для 3x-ui 3.7.0. Основной репозиторий: https://github.com/KabanProduct/APP_3x-ui, ветка `main`.

Текущий порядок работы по указанию пользователя: **накапливать изменения локально, без сборки APK и публикации каждого изменения**. Записывать пожелания, реализацию и оставшиеся задачи в `docs/backlog.md`. Не запускать сборку APK, release workflow и не отправлять изменения на GitHub до отдельной явной команды пользователя «выполни сборку и публикацию» или равнозначной. Push в `main` запускает CI, поэтому также отложен. Во время доработок выполнять только необходимые целевые проверки без упаковки APK; полную проверку накопленных изменений проводить перед выпуском.

Только после явной команды на сборку и публикацию:

1. Проверить изменения подходящими тестами. На Windows использовать `scripts/build.ps1`; он решает проблему кириллицы в пути через временный SUBST.
2. Для выпуска новой версии увеличить **versionCode и versionName** в `app/build.gradle.kts`, добавить `docs/releases/<versionName>.md` с фактическими изменениями и ограничениями.
3. Проверить состав коммита, отправить изменения в `main` и дождаться результата GitHub Actions. Исправлять ошибки выпуска; не сообщать о публикации до появления готового Release.
4. В ответе дать ссылку на Release/APK и кратко описать проверки и оставшиеся ограничения.

GitHub Actions сам создаёт тег и Release после успешных проверок, если версия ещё не опубликована. Не перезаписывать выпущенные APK. Изменения только документации не требуют новой версии приложения.

Сохранять applicationId `dev.threex.mobile` и постоянный ключ подписи. `.signing/` содержит приватный ключ и пароль; не читать их в вывод инструментов, не коммитить и не публиковать. Для CI используются существующие GitHub Secrets; ключ не пересоздавать. Подробности: `docs/releases.md`.

Не коммитить `.tools/`, `.research/`, временные тестовые APK, пароли панелей, SSH-ключи, токены и данные пользователей. Не запускать тесты, удаляющие приложение или меняющие VPN, на физическом телефоне пользователя без его указания; для таких проверок использовать принадлежащий задаче эмулятор.

Установка на настоящий VPS, удаление ресурсов и изменение работающего сервера требуют явного пользовательского задания. Наличие исходников установщика не является разрешением выполнять его на чужом сервере.
