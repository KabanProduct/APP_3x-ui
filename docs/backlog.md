# Накопленные доработки

Работаем локально. Сборка APK и публикация на GitHub — только по отдельной команде пользователя. Последний опубликованный релиз: 0.3.0.

Для каждого пожелания фиксировать: ожидаемое поведение, статус реализации, проведённые проверки и нерешённые вопросы. Реализацию не считать проверенной на устройстве до соответствующего испытания.

## Пожелания

### 1. Автозаполнение публичного адреса в мастере

- Статус: реализовано; включено в пакет 0.3.0.
- Пожелание: заполнять поле публичного IP автоматически из адреса подключённого сервера панели, сохранив возможность ручного изменения.
- Ожидаемое поведение: при открытии мастера подставлять хост активного сервера без схемы, порта и пути панели. Если панель подключена по домену, использовать домен как адрес подключения, не выдавая его за установленный публичный IP.
- При реализации учесть: адрес панели через reverse proxy или туннель может отличаться от адреса VPN; пользователь должен иметь возможность исправить предложенное значение.
- Реализация: хост извлекается из адреса активной панели, порт и секретный путь исключаются; поле остаётся редактируемым и обновляется при смене сервера.
- Проверки: unit-тесты IPv4, доменного имени и IPv6; компиляция Kotlin успешна.

### 2. Автозаполнение SNI и REALITY target с выбором доменов сервера

- Статус: реализовано; включено в пакет 0.3.0. Проверка на реальной панели ещё нужна.
- Пожелание: автоматически заполнять SNI и REALITY target, предлагать домены на выбор и случайный вариант, как в веб-интерфейсе 3x-ui. Подтягивать предложения с подключённого сервера.
- Ожидаемое поведение: согласованно заполнять оба поля, предоставлять выбор предложений и возможность ручного изменения.
- Источник подтверждён по исходникам 3x-ui 3.7.0: POST `panel/api/server/scanRealityTargets`, form `targets=`. Сервер сам выбирает стандартный список и проверяет кандидатов. Используются только пригодные публичные результаты; список в приложение не зашит.
- Реализация: автоматическая загрузка в REALITY-мастере, случайное заполнение пустой пары SNI/target, выпадающий выбор, кнопки случайного выбора и повторной проверки. Введённые вручную значения не затираются после ответа сервера. Для XHTTP + TLS чужие REALITY-домены не подставляются.
- Проверки: unit-тест отбора кандидатов, MockWebServer-проверка URL, POST и пустого targets; компиляция Kotlin успешна.

### 3. Исправление создания клиента и полноценная форма

- Статус: форма и создание переработаны; Android-тест видимости полей, выбора Flow/входящего и отправки формы прошёл. Создание на пользовательской панели ещё не проверено.
- Проблема со слов пользователя: создание клиента не работает, форма не показывает поля, клиенты не создаются.
- Пожелание: восстановить создание клиентов и перенести необходимые поля формы из 3x-ui 3.7.0. Особенно важны **Flow** и **привязанные входящие (inbounds)**, включая выбор нескольких входящих, если это поддерживается панелью.
- Ожидаемое поведение: форма отображает поля, позволяет задать Flow и привязки, отправляет корректный запрос API; созданный клиент появляется в списке с заданными параметрами. Ошибки валидации и сервера видны пользователю.
- При реализации: сопоставить полный набор полей, значения по умолчанию, обязательность и ограничения с формой и API 3x-ui 3.7.0; проверить UUID/идентификатор, имя/email, включение доступа, лимиты трафика и IP, срок действия и прочие доступные параметры. Проверить совместимость Flow с протоколом и транспортом выбранных входящих.
- Реализация: отдельная форма VLESS с ограниченной высотой и прокруткой, множественным выбором входящих, Flow, UUID/генерацией, ID подписки, включением доступа, лимитами ГиБ/IP/HWID, четырьмя режимами срока, продлением, сбросом трафика, Telegram ID, группой, комментарием и reverse tag. Flow проверяется на совместимость со всеми выбранными входящими. Другие протоколы пока не добавлены.
- Создание отправляет `{client, inboundIds}`; форма закрывается только после успешного ответа. При ошибке поля сохраняются, ошибка показана в форме. После создания обновляется список. Учтено, что 3.7.0 принудительно создаёт включённого клиента: для выключенного доступа следует отдельный запрос, а при его сбое сообщение явно говорит о уже созданном клиенте.
- Дополнительно: импорт VLESS на телефон принимает `xtls-rprx-vision-udp443`.
- Проверки: unit-тесты полей запроса, дробных лимитов/байтов, сроков и отложенного старта, UUID/идентификаторов, привязок и Flow; MockWebServer-проверка запроса создания. Отображение и отправка формы проверены Android-тестом. Реальная панель ещё не проверена.
